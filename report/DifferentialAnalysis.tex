    \section{Introduction}\label{sec:introduction}
    RNA sequencing (RNAseq) is a powerful and widely used method for analyzing the transcriptome, providing insights into gene expression patterns, alternative splicing, and the discovery of novel transcripts. By converting RNA into complementary DNA (cDNA) and sequencing it using high-throughput platforms, researchers can quantify and characterize the complete set of RNA transcripts (those that are sequencable) present in a sample. The results of an RNAseq experiment are a set of sequenced reads in the FASTQ format, either single-end or paired-end. These reads are then mapped back onto the reference genome using a mapper such as \texttt{STAR}~\cite{star}.

    A typical RNAseq workflow includes sample extraction, sequencing, mapping, annotation, and downstream analyses such as differential expression analysis. In a perfect scenario, each read originates from exactly one transcript. However, sometimes it is unclear from which transcript or even gene a read originates. Additionally, annotations can be incomplete, sequencing or mapping errors can occur, and genes or transcripts can overlap, complicating the mapping process. The annotation steps attempt to quantify and correct these errors, sort out improbable or incorrect reads, and assign reads to genes.

    Strand specificity in RNA sequencing refers to the ability to determine the strand of DNA from which an RNA transcript originates. This property is important because transcription is inherently directional, with RNA synthesized from only one DNA template strand. Strand-specific sequencing protocols preserve this directionality, allowing researchers to distinguish between overlapping genes transcribed on opposite strands or sense and antisense transcription. The need for strand specificity arises from the complexity of eukaryotic genomes, where overlapping genes, antisense transcription, and non-coding RNAs are common. It can be challenging to accurately assign reads to their source transcripts without strand-specific information, leading to ambiguous or erroneous interpretations. By maintaining strand specificity, RNAseq enables a more precise understanding of transcriptional regulation, splicing, and gene expression patterns. Importantly, all experiments used in this project are unstranded.


    \subsection[SAM Format]{Sequence Alignment Map Format}
    The Sequence Alignment Map (SAM) format is a widely used text-based format for storing biological sequences that are aligned to a reference genome. Each entry in a SAM file contains detailed information about a read and its alignment, such as the alignment positions and possible mismatches. While SAM files are human-readable, they are relatively large in size, as each field is stored as plain text.

    BAM files are the binary equivalent of SAM files, designed to store the same alignment information in a compressed and efficient manner. Unlike the plain-text SAM format, BAM files use binary encoding to represent data, significantly reducing their storage requirements. For example, when storing numbers in plaintext encoded in UTF-8, the number '64' would be encoded as the characters '6' and '4', each requiring 8 bits. In contrast, the binary representation of 64 would be \texttt{01000000}, which is 8 bits in total. This is an oversimplified example but it illustrates some of the advantages of the binary format. BAM files can be indexed and sorted by name or position, enabling fast access to specific regions of interest. However, this means that a single forward/reverse read pair might not appear consecutively, as the reads are sorted by their position on the reference genome. Several read inconsistencies occur in BAM files that should be excluded from analysis:
    \begin{itemize}
        \item Reads in a pair mapping to different chromosomes.
        \item Both reads in a pair mapping to the same strand.
        \item Overlapping reads in a pair that imply different introns (see Figure \ref{fig:overlapping-inconsistent-blocks}).
    \end{itemize}

    When annotating, the goal is to identify the most plausible explanation for each read based on its alignment and features. A read may originate from a transcript, reflecting active transcription within an annotated gene, or from a gene's transcribed region but not its exons, such as an intronic region or a novel isoform—especially if splicing events are observed. Alternatively, reads may align antisense to known transcripts, potentially indicating by-products or genuine antisense transcription. Some reads may be classified as intergenic, often aligning near gene boundaries. This could signal novel isoforms or unannotated untranslated regions (UTRs).

    \subsection{Read Mapping Types}

    To accurately classify read pairs, it is essential to define the different types of mappings. A consistent read pair can be classified as \texttt{genic}, \texttt{intergenic}, or \texttt{intergenic containing}. A genic read pair is one where both reads in a pair are contained within a gene. Formally, this means all mapped bases of the read are greater than or equal to the gene start position and less than or equal to the gene end position (inclusive). A read pair is \texttt{intergenic} if it is not \texttt{genic} and does not completely contain one or more genes. A read contains a gene if the first mapped base of the read is less than or equal to the start of the gene and the last mapped base is greater than or equal to the end of the gene. All other read pairs are \texttt{intergenic-contained}.

    A \texttt{genic} read pair can be further classified as \texttt{transcriptomic}, \texttt{merged-transcriptomic}, or \texttt{intronic}. A read pair is considered \texttt{transcriptomic} if it is fully contained within at least one annotated transcript and aligns contiguously to a specific transcript sequence section (see Figure~\ref{fig:transcriptomic-read}). This means that the intron boundaries observed in the read pair are consistent with those defined in the transcript annotation. Formally, a read pair matches a transcript if both read Region Vectors (RVs) are sub-RVs (defined later) of at least one transcript.

    A read pair is classified as \texttt{merged-transcriptomic} if it aligns to the merged transcript of a gene but does not necessarily match contiguously (Figure \ref{fig:merged-transcriptomic-read}). The merged transcript represents the union of all exonic regions of a gene, disregarding specific intron boundaries. This classification accounts for reads that may span novel isoforms or unannotated transcripts. Formally, a read pair matches the merged transcript if each base of the read pair aligns with some exon in the merged transcript. This broader definition enables the identification of potential new transcript variants while maintaining consistency with the gene's exon structure.

    A read pair is classified as \texttt{intronic} if it is fully contained within the gene body but does not align to any annotated transcript or merged transcript (Figure \ref{fig:intronic-read}). Intronic reads may represent unprocessed RNA, novel isoforms with unannotated intron retention, or other transcriptional events within the gene body.

    Since we are only looking for the most biologically plausible explanation, we only want to consider the most plausible case (\texttt{transcriptomic} $>$ \texttt{merged-transcriptomic} $>$\texttt{intronic}). For example, if a read pair matches a specific transcript of one gene but also the merged transcript of another gene, we would only consider the transcriptomic match as it is more plausible. If a read pair matches multiple transcripts of multiple genes, we would want to know all the matched transcripts.

    \subsection{Evidence of Alternative Splicing}\label{subsec:evidence-of-alternative-splicing}
    Since reads can map to specific transcripts of a gene, it is possible that a read might indicate the inclusion or exclusion of a specific exon. An example of a evidence for an exon skipping event is shown in Figure~\ref{fig:example-exon-skipping-event}. Some reads provide evidence for the inclusion of an exon (inclusion reads), while others provide evidence for the exclusion of an exon (exclusion reads). Additionally, even though some reads might map to a gene, they do not provide evidence for the inclusion or exclusion of a specific exon. These reads are considered ambiguous.

    The Percent Spliced In (PSI) value is a metric used to quantify the inclusion of an exon in a transcript. It is calculated using the formula shown in Equation \ref{eq:psi}. The PSI value ranges from 0 to 1, where 0 indicates that the exon is always excluded, and 1 indicates that the exon is always included. The PSI value is calculated by dividing the number of inclusion reads by the sum of inclusion and exclusion reads. The PSI value is calculated for each exon in an exon skipping event.

    \section{Materials and Methods}\label{sec:materials-and-methods}

    \subsection{Provided Files}\label{subsec:provided-files}

    The following files were provided for the analysis of alternative splicing events and served as key resources for the various analyses:

    \begin{itemize}
        \item \texttt{bam/}: This directory contains BAM files, which represent the aligned sequencing reads.
        \item \texttt{annotation\_b37.gtf}: This file contains the transcript annotation in GTF format. It provides structural information about transcripts, including exon and intron boundaries, which are critical for mapping reads to specific genomic features.

        \item \texttt{differential\_exons.RData}: This RData file includes the ground truth for the exons identified in the annotation file. It serves as a reference for validating the results of exon-level differential expression analyses.

        \item \texttt{diff\_psi\_test.RData}: This file contains data for testing the method for likelihood ratio testing (LRS) in the context of differential splicing.
        \item \texttt{AlternativeSplicing/}: Contains partial reference solutions for testing.
    \end{itemize}

    \subsection{Compute Percent-Spliced-In (PSI) values}\label{subsec:compute-percent-spliced-in-(psi)-values-materials-and-methods}
    Figure \ref{fig:alternative-splicing-process} shows the general process for solving the BamFeatures assignment. Due to the complexity of this assignment and the numerous cases, a flowchart is optimal for understanding the task. This allows optimal structuring of an implementation, as one can see which checks can be performed first, in order to possibly rule out other checks from needing to be made, saving computation time. The flowchart shows the process of processing a single read but differs from the actual implementation due to structural reasons. This is because the implementation processes the reads in batches (by chromosome), instead of one by one. The general structure of the program is described below:
    \begin{enumerate}
        \item \textbf{Initialization and Setup}: Creation of the \texttt{AlternativeSplicingAnnotator} object which initializes the \texttt{GTFAnnotation}, calculates the exon skipping events (as per the first report), as well as initializing the \texttt{SamReader}, and \texttt{IntervalTreeForestManager}. The exon skipping events are stored so that each individual exon that is skipped as a part of an exon skipping event has its own inclusion and exclusion count.
        \item \textbf{Iteration Process}:
        \begin{enumerate}
            \item \textbf{Iterate through the SamReader}: Iterate to the next record, unless the end of the file is reached in which case go to step \ref{sec:last-chromosome-processing} \label{sec:iterate-samreader}
            \item \textbf{Chromosome Check}: Check if the current record is on the same chromosome as the previous record. If not, process the reads in step \ref{sec:new-chromosome-processing}. \label{sec:chromosome-check}
            \item \textbf{Valid Read Check}: Check conditions if the read is valid. If not, continue to step \ref{sec:iterate-samreader}.
            \item \textbf{Read Pair Check}: Check if we have seen the record's mate before:
            \begin{itemize}
                \item If yes, add the records in the correct order (first of pair) to the readsToAnnotate List
                \item If no, add the record to the lookup table and continue to the next record.
            \end{itemize}
            \item Go to step \ref{sec:iterate-samreader}.
        \end{enumerate}
        \item \textbf{New Chromosome Processing} \label{sec:new-chromosome-processing}:
        \begin{enumerate}
            \item \textbf{Read Processing}: \label{sec:read-processing}
            \begin{enumerate}
                \item Calculate the Read's attributes such as the combined read intervals, extracting alignment start and end, etc.
                \item If there are any \texttt{cgenes}, check for a transcriptomic match. Otherwise, skip the the next read.
                \item For each matched gene with a transcriptomic match, iterate through the exon skipping events for that gene (by skipped exon).
                \item If the matched transcripts equal the Wild Type transcripts of the exon skipping event \& the read alignment overlaps the skipped exon, the inclusion count is incremented. Specifically, the start of the read alignment is before or at the end of the skipped exon, and the end of the read alignment is after or at the start of the skipped exon. This ensures that the read covers at least part of the skipped exon.
                \item If the matched transcripts equal the Splice Variant transcripts of the exon skipping event \& the read alignment fully contains the skipped exon, the exclusion count is incremented. Specifically, the start of the read alignment is before the start of the skipped exon, and the end of the read alignment is after the end of the skipped exon. This ensures that the read fully contains the skipped exon and is not an ambiguous read.
                \item Repeat this process for all exons in each exon skipping event for each matched gene.
            \end{enumerate}
            \item Reset the data structures and return to step \ref{sec:chromosome-check}.
        \end{enumerate}
        \item \textbf{Last Chromosome Processing} \label{sec:last-chromosome-processing}:
        \begin{enumerate}
            \item Process the reads like in Step \ref{sec:read-processing}.
            \item Calculate the PSI score for each exon for each exon skipping event.
            \item If either the inclusion or exclusion count is greater than 0, the result is printed to the output file in the format shown in Table \ref{tab:psi-output-format}.
        \end{enumerate}
    \end{enumerate}
    Since the iteration process through the BAM file and caching (by chromosome) process is the same as the BamFeatures task, an abstract class, \texttt{ReadAnnotator}, was created. The abstract class implements the iterating, read validation checking (see previous report) and stores the required data structures (lookup table, forest manager). While iterating through the BAM file, the abstract class calls up the \texttt{processNewChromosome} and \texttt{processLastChromosome} methods, which are implemented in the respective annotator (\texttt{AlternativeSplicingAnnotator} \& \texttt{FeatureCountAnnotator}). The exon skipping events are processed in an identical fashion to the first report, with the only difference being that the inclusion and exclusion counts are stored for each exon in the exon skipping event. These events are then stored in a map, where the key is the gene id.

    In this task, we consider strand unspecific experiments, meaning that we always check both strands for a gene match. When iterating through the \texttt{SAMRecords}, if the read is from a new chromosome, all reads from the previous chromosome are processed. Since the file is organized by chromosome and position, the lookup data structures can be reset. Before adding a read to the lookup table, it is checked for validity:
    \begin{enumerate}
        \item The read is mapped
        \item The read is part of a pair
        \item The mate read is mapped
        \item The reads are on different strands
        \item The reads are on the same chromosome
        \item The read is not a supplementary alignment
    \end{enumerate}
    This check ensures that only valid reads are processed, guaranteeing the correctness of the annotation. Since both records of the first and second read in a pair are needed, processing cannot begin until both reads are found. A lookup table is used to match reads with their mates. If the mate has not been found yet, the read is added to the table using the read name, which is the same for paired reads but unique across the experiment. Once the mate is found, both reads are added to the \texttt{readsToAnnotate} list in the correct order. After processing the entire chromosome, all pairs in \texttt{readsToAnnotate} are annotated, and any remaining entries in the lookup table are ignored.

    The annotation of a read pair begins with extracting the alignment's start and end positions. These coordinates are then used to find the genes on the current chromosome that fully include the read pair in their intervals. If there are any containing genes, we check if there is a transcriptomic match. To classify a read as transcriptomic, both reads' region vectors must be sub-region vectors of at least one transcript. A read region vector \(r\) is considered a sub-region vector of a transcript \(t\) if \(\text{cut}(t, r_{\text{start}}, r_{\text{end}}) = r\), as shown in Figure~\ref{fig:transcriptomic-cut}.
    \begin{figure}[!htpb]
        \centering
        \includegraphics[width=0.7\textwidth]{figures/BamFeatures/transcriptomic-cut}
        \caption
        {Diagram showing how the cut method works for checking if a read matches a transcript. The transcript is cut starting from the first base of the read and ending at the last base of the read. If the cut transcript is the same as the read, the read matches the transcript.}
        \label{fig:transcriptomic-cut}
    \end{figure}
    For all the matching genes (in case there are multiple), we iterate through the exon skipping events. If the matching transcripts (from the transcriptomic match) equal the Wild Type transcripts of the exon skipping event and the read alignment overlaps the skipped exon, the inclusion count is incremented. If the matching transcripts equal the Splice Variant transcripts of the exon skipping event and the read alignment fully contains the skipped exon, the exclusion count is incremented. This process is repeated for all exons in each exon skipping event for each matched gene. After processing all reads, the PSI score is calculated for each exon in each exon skipping event. If either the inclusion or exclusion count is greater than 0, the result is printed to the output file in the format shown in Table~\ref{tab:psi-output-format}.

            \begin{tabular}{l|l|l|l|l|l}
                gene & exon & num\_incl\_reads & num\_excl\_reads & num\_total\_reads & psi
            \end{tabular}%
        }
    \end{table}

    \subsection{Simple Differential Test of PSI-Values}\label{subsec:simple-differential-test-of-psi-values}

    To evaluate whether the Percent Spliced In (PSI) values differ between two groups, we assume a simple statistical model based on the binomial distribution. This test compares two probability models: a reduced model and a full model.

    \subsubsection{The Binomial Model for PSI-Values}
    The probability of observing $i$ inclusion reads out of $N$ total reads, given the inclusion probability $p$, is described by the binomial distribution:
    \begin{equation}
        P(i|p,N) = \binom{N}{i} \cdot p^i \cdot (1-p)^{N-i}
        \label{eq:binomial-distribution}
    \end{equation}
    where \( \binom{N}{i} \) is the binomial coefficient, \( p \) is the inclusion probability, and \( N \) is the total number of reads (inclusion + exclusion reads). The inclusion probability \( p \) corresponds to the PSI ratio. This formula provides the foundation for both models. With the assumption of independence between reads, the likelihood of the observed data is calculated as the product of the binomial probabilities for all samples.
    To find the MLE of the inclusion probability \( p \) for the binomial distribution, we maximize the likelihood function:
    \begin{equation}
        L(p) = \prod_{j=1}^{n} \binom{N_j}{i_j} p^{i_j} (1-p)^{N_j - i_j},
    \end{equation}
    where \( n \) is the number of samples, \( i_j \) is the inclusion count, and \( N_j \) is the total read count for sample \( j \).

    Taking the natural logarithm of the likelihood simplifies the product to a sum:
    \begin{equation}
        \log L(p) = \sum_{j=1}^{n} \left[ \log \binom{N_j}{i_j} + i_j \log(p) + (N_j - i_j) \log(1-p) \right].
    \end{equation}

    The binomial coefficient \( \binom{N_j}{i_j} \) does not depend on \( p \) and can be ignored during differentiation. The relevant terms are:
    \begin{equation}
        \log L(p) = \sum_{j=1}^{n} \left[ i_j \log(p) + (N_j - i_j) \log(1-p) \right].
    \end{equation}

    To maximize \( \log L(p) \), take the derivative with respect to \( p \) and set it to zero:
    \begin{align}
        \frac{\partial \log L(p)}{\partial p} &= \sum_{j=1}^{n} \left[ \frac{i_j}{p} - \frac{N_j - i_j}{1-p} \right] = 0.
    \end{align}

    Simplifying and solving for \( p \):
    \begin{align}
        \sum_{j=1}^{n} \frac{i_j}{p} &= \sum_{j=1}^{n} \frac{N_j - i_j}{1-p}, \\
        \frac{\sum_{j=1}^{n} i_j}{p} &= \frac{\sum_{j=1}^{n} (N_j - i_j)}{1-p}, \\
        \frac{\sum_{j=1}^{n} i_j}{p} &= \frac{\sum_{j=1}^{n} N_j - \sum_{j=1}^{n} i_j}{1-p}.
    \end{align}

    Let \( I = \sum_{j=1}^{n} i_j \) (total inclusion reads) and \( N = \sum_{j=1}^{n} N_j \) (total reads). Substitute these terms:
    \begin{align}
        \frac{I}{p} &= \frac{N - I}{1-p}.
    \end{align}

    Cross-multiply and simplify:
    \begin{align}
        I (1-p) &= (N - I) p, \\
        I - I p &= Np - I p, \\
        I &= Np, \\
        p &= \frac{I}{N}.
    \end{align}

    Thus, the MLE for \( p \) is:
    \begin{equation}
        \hat{p} = \frac{\sum_{j=1}^{n} i_j}{\sum_{j=1}^{n} N_j}.
        \label{eq:binomial-mle}
    \end{equation}

    \subsubsection{The Reduced Model}
    The reduced model assumes that all samples share a common inclusion probability \( p_0 \). Under this model, the likelihood of the observed data for all samples is:
    \begin{equation}
        L_{reduced}(p_0) = \prod_{j=1}^{10} P(i_j, N_j|p_0)
        \label{eq:reduced-likelihood}
    \end{equation}
    where \( i_j \) and \( N_j \) are the inclusion and total reads for sample \( j \). Using the log-likelihood simplifies computation:
    \begin{equation}
        \log L_{reduced}(p_0) = \sum_{j=1}^{10} \left[ \log \binom{N_j}{i_j} + i_j \log(p_0) + (N_j - i_j) \log(1-p_0) \right]
        \label{eq:log-reduced-likelihood}
    \end{equation}

    The maximum likelihood estimate (MLE) for \( p_0 \) is calculated by maximizing this log-likelihood:
    \begin{equation}
        p_0 = \frac{\sum_{j=1}^{10} i_j}{\sum_{j=1}^{10} N_j}
        \label{eq:p0-mle}
    \end{equation}

    \subsubsection{The Full Model}
    The full model allows for separate inclusion probabilities \( p_1 \) and \( p_2 \) for the two groups. As an example, consider two groups of five samples each:
    \[
        \text{Group 1: } \{p_1, p_1, p_1, p_1, p_1\}, \quad \text{Group 2: } \{p_2, p_2, p_2, p_2, p_2\}
    \]
    The likelihood of the data under the full model is:
    \begin{equation}
        L_{full}(p_1, p_2) = \prod_{j=1}^{5} P(i_j, N_j|p_1) \cdot \prod_{j=6}^{10} P(i_j, N_j|p_2)
        \label{eq:full-likelihood}
    \end{equation}
    The corresponding log-likelihood is:
    \begin{equation}
        \log L_{full}(p_1, p_2) = \sum_{j=1}^{5} \left[ \log \binom{N_j}{i_j} + i_j \log(p_1) + (N_j - i_j) \log(1-p_1) \right]
        + \sum_{j=6}^{10} \left[ \log \binom{N_j}{i_j} + i_j \log(p_2) + (N_j - i_j) \log(1-p_2) \right]
        \label{eq:log-full-likelihood}
    \end{equation}

    The MLEs for \( p_1 \) and \( p_2 \) are:
    \begin{align}
        p_1 &= \frac{\sum_{j=1}^{5} i_j}{\sum_{j=1}^{5} N_j} \label{eq:p1-mle} \\
        p_2 &= \frac{\sum_{j=6}^{10} i_j}{\sum_{j=6}^{10} N_j} \label{eq:p2-mle}
    \end{align}

    \subsubsection{Likelihood Ratio Statistic and Hypothesis Testing}
    To test whether the PSI values differ between the two groups, we compute the likelihood ratio statistic (LRS):
    \begin{equation}
        LRS = -2 \cdot \log\left(\frac{L_{reduced}}{L_{full}}\right)
        \label{eq:lrs}
    \end{equation}
    which simplifies to:
    \begin{equation}
        LRS = -2 \cdot \left(\log L_{reduced} - \log L_{full}\right)
        \label{eq:lrs-log}
    \end{equation}

    Under the null hypothesis (\( H_0: p_1 = p_2 \)), the LRS follows a Chi-square distribution with one degree of freedom (\( df = 1 \)). The p-value is calculated as:
    \begin{equation}
        P(\text{LRS} > x) = 1 - F_{\chi^2}(x, df=1)
        \label{eq:p-value}
    \end{equation}
    where \( F_{\chi^2} \) is the cumulative distribution function of the Chi-square distribution.

    \subsubsection{Implemented R Functions in \texttt{LRS.R}}
    The analysis pipeline is built using two main functions:

    \paragraph{\texttt{LRS}}
    The \texttt{LRS} function performs the likelihood ratio test for a single exon. It takes three inputs:
    \begin{itemize}
        \item \texttt{incl}: A vector of inclusion read counts (IRC) for each sample.
        \item \texttt{total}: A vector of total read counts (IRC + ERC) for each sample.
        \item \texttt{group}: A vector indicating the group assignment (1 or 2) of each sample.
    \end{itemize}
    Using these inputs, the function:
    \begin{enumerate}
        \item Computes \( p_0, p_1, \) and \( p_2 \) as maximum likelihood estimates.
        \item Calculates the log-likelihoods for the reduced and full models.
        \item Derives the likelihood ratio statistic (LRS) and the corresponding p-value using the Chi-square distribution.
    \end{enumerate}
    The function returns a list containing \( p_0, p_1, p_2, \log L_{reduced}, \log L_{full}, \text{LRS}, \) and the p-value.

    \paragraph{\texttt{diff.splicing}}
    The \texttt{diff.splicing} function extends the \texttt{LRS} method for a dataset of multiple PSI files generated using the program described in Section~\ref{subsec:compute-percent-spliced-in-(psi)-values-materials-and-methods}. It:
    \begin{enumerate}
        \item Aggregates data from all input files (\texttt{psi.files}), merging metrics for each exon across samples.
        \item Processes each exon using \texttt{LRS}, storing results in a structured table.
        \item Adjusts p-values for multiple testing (Benjamini-Hochberg) and returns a final result with all columns listed below.
    \end{enumerate}

    The final output is a table containing:
    \begin{itemize}
        \item \textbf{gene, exon:} Identifiers for each exon being analyzed.
        \item \textbf{\( p_0, p_1, p_2 \):} Maximum likelihood estimates of the inclusion probabilities under the reduced and full models.
        \item \textbf{\( \log L_{reduced}, \log L_{full} \):} Log-likelihoods for the reduced and full models.
        \item \textbf{lrs:} Likelihood ratio statistic, quantifying the improvement of the full model over the reduced model.
        \item \textbf{pvalue:} Statistical significance of the observed LRS.
        \item \textbf{padj:} Adjusted p-values for controlling the false discovery rate (FDR).
    \end{itemize}

    We computed the following metrics:
    \begin{itemize}

        \item \textbf{False Discovery Rate (FDR)}: The proportion of false positives among all predicted positives.
        \item \textbf{ROC Curves and AUC}: ROC curves were generated to visualize the trade-off between true positive rate (TPR) and false positive rate (FPR). The area under the curve (AUC) was calculated to quantify overall performance.
    \end{itemize}

    \subsubsection{Statistical Analysis and Visualization}

    \begin{enumerate}
        \item Generating ROC curves for both methods using \texttt{padj} values as classifiers.
        \item Plotting the curves on the same graph for visual comparison, with AUC values included in the legend.
        \item Calculating sensitivity and FDR for predictions with \texttt{padj < 0.05}.
    \end{enumerate}

    \subsubsection{Correctness}

    Wild Type (WT) transcripts are defined as those that include all exons within the exon skipping event, while Splice Variant (SV) transcripts are those that omit one or more of these exons. If the matching transcripts of a read equal WT transcripts of an exon skipping event, it implies that it doesn't match the SV transcripts. If the read were to exclude one of the exons in the exon skipping event, it should match the SV transcripts. If it matches part of WT and SV, we can naturally conclude it is an ambiguous read. To ensure that the read provides evidence of inclusion of a specific exon(s) in an event, we have to check whether the read alignment overlaps with the skipped exon. The process for an exclusion is analogous, but this time it is checked whether the read alignment fully contains the skipped exon. This WT/SV approach provides a computationally efficient way to determine the inclusion/exclusion status of a read while also ensuring correctness.

            \item FDR: 0 (no false positives).
        \end{itemize}
        \item \textbf{LRS Method:}
        \begin{itemize}
            \item Sensitivity: 0.9677 (~96.8\% true positives detected).
            \item FDR: 0.0323 (~3.2\% false positives).
        \end{itemize}
    \end{itemize}


    The results indicate that both methods effectively identify differentially spliced exons. While the overall AUC was higher for the LRS method, the DEXSeq method performed better given a p-value threshold of 0.05. In the case, the DEXSeq method achieved perfect sensitivity and no false positives, while the LRS method had a slightly lower sensitivity and a small FDR. This comparison establishes the LRS-based approach as a viable alternative to DEXSeq for differential alternative splicing analysis, highlighting the fact that preexisting tools don't always outperform a purpose-built self-developed method.
